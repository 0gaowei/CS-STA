# 2026 秋季 Agent 应用学习路线

这份路线为希望用 AI 解决实际问题的同学提供自学参考，涵盖使用现成 Agent、扩展 Agent 能力和开发应用。可以按顺序入门，也可以根据自己的基础和兴趣选择部分内容，学习节奏自行安排。Python、Git 和 API 基础可随项目逐步补齐；已有开发经验的同学可以直接从感兴趣的实践开始。

## 学习重点

学习主线：**使用 Agent 完成任务 → 用 Skills 和工具扩展能力 → 编写自己的 Agent → 验证效果与整理项目。**

建议重点关注任务设计、工具接入、上下文管理和结果验证。Coze 等平台适合快速体验，Python 用于理解和实现功能，SDK 与框架用于组织应用。下面的能力清单可以用来了解自己学到了哪里。

- [ ] 能把实际需求写成清楚的输入、约束、交付物和验收标准。
- [ ] 能使用现成 Agent 完成多步任务，并检查文件、数据或代码等实际产物。
- [ ] 能编写和改进一个 Skill，区分提示词、Skill、工具调用和 MCP 的作用。
- [ ] 能调用模型 API，开发带工具调用和停止条件的单 Agent 应用。
- [ ] 能按任务需要组织资料、检索信息、保存状态，并定位一次失败的原因。
- [ ] 能做出可复现的 Demo，用固定案例比较改进前后的效果、耗时和成本。

## 学习安排

下表提供一个约 12 周的参考节奏，实际用时取决于个人基础和投入，可以跳过熟悉的内容，也可以在感兴趣的阶段多做探索。建议选一个自己想解决的小问题，让后续练习围绕同一项目逐步展开。

| 阶段 | 参考时间 | 核心问题 | 练习参考 |
| --- | --- | --- | --- |
| 使用 Agent | 第 1–2 周 | 怎样委派任务，并判断它是否完成？ | 尝试一个真实任务并检查结果 |
| 扩展能力 | 第 3–4 周 | 怎样让 Agent 按自己的方法工作？ | 可复用 Skill 及对照案例 |
| 构建应用 | 第 5–6 周 | 工具调用和 Agent 循环如何运行？ | 本地运行的单 Agent 原型 |
| 接入资料与工具 | 第 7–8 周 | 怎样提供合适的信息和外部能力？ | MCP 接入与上下文改进记录 |
| 提高可靠性 | 第 9–10 周 | 怎样发现失败、控制执行并验证改进？ | 评测集、执行日志和一次修复 |
| 整理项目 | 第 11–12 周 | 怎样让其他人也能使用？ | 可复现的 Demo 与使用说明 |

### 第一阶段：使用 Agent 完成真实任务

选择一个当前可访问的 Agent 工具，例如编程 Agent、扣子或其他支持工具执行的应用。围绕自己的学习或社团工作，完成一次需要读取资料、执行操作并生成结果的任务。

- 理解普通对话、固定工作流和 Agent 的区别：哪些步骤预先确定，哪些步骤由模型根据执行结果决定。
- 练习描述目标、提供必要资料、约束操作范围，观察 Agent 如何使用文件、搜索或代码工具。
- 补齐终端基本操作、目录与文件管理，以及 Git 的提交、查看差异和回退方法。
- 验收实际产物，记录一次失败及原因，例如需求不清、资料缺失、工具不可用或结果未经验证。

**自检参考：**能否解释 Agent 做了什么、结果是否满足需求、哪些地方需要人工介入？用 AI 辅助编码时，可以尝试读懂关键修改，并重新运行验证结果。

### 第二阶段：用 Skills 沉淀可复用的方法

选择一个会重复遇到的任务，例如整理活动记录、检查项目 README、按模板生成技术周报，将操作步骤、参考资料和输出模板封装成 Skill。

- 学习 `SKILL.md` 中名称、描述与执行说明的作用，写清适用场景和触发条件。
- 将参考资料、模板和确定性处理脚本分别组织，练习按需读取。
- 理解能力分工：Skill 提供任务方法；工具执行具体操作；MCP 用于连接外部工具与数据。Skill 中写出的要求仍需运行环境和检查机制支持。
- 选几个案例比较使用 Skill 前后的结果，也试试不应触发该 Skill 的任务，根据失败原因调整说明。

**自检参考：**Skill 能否在合适的任务中被使用，输出是否更符合预期？换一种提问或输入后，方法是否仍然有效？

### 第三阶段：编写一个带工具的 Agent

从调用一次模型 API 开始，逐步开发能调用工具并根据结果继续执行的本地应用。先弄清基本执行过程，再选择一个 SDK 或框架组织项目。

- 补齐 Python 的函数、列表与字典、模块、文件与 JSON 处理、异常处理、虚拟环境和依赖管理。
- 理解请求与响应、消息历史、结构化输出、Token 用量，以及鉴权失败、限流和超时等常见问题。
- 尝试编写一个自定义工具，明确参数、返回值和错误信息，例如检索本地资料或查询活动安排。
- 跑通“模型请求工具 → 程序执行 → 返回结果 → 模型继续或结束”的过程，设置最大步数和超时，保存执行日志。

**自检参考：**能否从日志中找到一次工具调用的输入、输出和后续处理？应用遇到错误或达到执行上限时，是否能停止并给出说明？

### 第四阶段：接入 MCP 与管理上下文

围绕项目实际需要接入外部能力，并解决“Agent 在这一步需要哪些信息”的问题。

- 了解 MCP 中应用、客户端和服务端的关系，接入一个可信、范围明确的 MCP 服务，记录它提供的能力。
- 区分任务指令、参考资料、工具结果和会话历史，练习只加载当前任务需要的信息。
- 比较直接读取资料、关键词搜索与 RAG（检索增强生成）的适用场景；资料规模和检索需求合适时再引入向量检索。
- 用文件或数据库保存任务进度，区分会话历史、任务状态与长期记忆，尝试中断后恢复。

**自检参考：**能否说明 MCP 接入后增加了什么能力，上下文调整前后的结果有什么差别？知识问答类应用是否能指出依据，并识别资料不足的情况？

### 第五阶段：评测、调试与执行控制

理解 Agent harness：围绕模型组织工具执行、上下文、状态、权限、恢复和日志的运行机制。使用现成 SDK 或框架实现项目所需的部分。

- 从项目中积累一组固定评测案例，尝试覆盖正常任务、缺少信息、工具失败和超出权限范围等情形，写清预期结果。
- 同时检查最终结果与关键执行行为。例如声称生成文件时检查文件是否存在，要求只读时检查是否发生写入。
- 记录任务结果、耗时、工具调用次数和可获得的用量数据；对容易波动的案例重复运行，注明模型与配置。
- 根据日志定位一次具体失败，修改提示词、Skill、工具或执行逻辑，再运行同一组案例比较结果。
- 为项目配置密钥管理、操作范围、执行预算，以及写入或对外操作前的确认；区分检索材料中的指令与用户任务。

**自检参考：**一次修改是否真的改善了效果，能否用相同案例验证？除了成功率，耗时、成本和失败后的表现是否也符合自己的需求？

### 第六阶段：整理项目与分享

项目有了基本功能后，可以整理成方便自己复用、也方便他人尝试的 Demo。优先跑通一个清楚、完整的任务流程，再考虑扩大范围。

- 整理依赖、配置示例、启动方式、输入样例和输出说明。
- 提供命令行、简单网页或其他适合目标用户的入口。
- 有机会时邀请同学试用，根据反馈改进。
- 分享时说明需求、执行过程、实际产物、评测结果和已知限制。

**自检参考：**过一段时间后，自己能否按文档重新运行项目？感兴趣的同学能否看懂它解决什么问题、怎样使用？愿意分享的话，欢迎参考 [Demo 提交规范](./demo/README.md)，将成果放到 [demo/](./demo/)。

## 项目选题

从自己能提供资料、能判断结果是否正确的场景开始。每个项目先明确一个主要用户和一个核心任务。

| 选题 | 最小可交付范围 | 重点验证 |
| --- | --- | --- |
| 社团资料助手 | 检索公开活动资料，回答问题并标出出处 | 依据是否正确，资料缺失时如何处理 |
| 技术调研助手 | 对指定主题检索来源，生成带链接的比较报告 | 来源日期、事实准确性和引用对应关系 |
| 项目文档助手 | 检查指定仓库的 README 与启动说明，输出修改建议 | 是否实际检查文件，建议能否复现 |
| 活动复盘助手 | 从会议记录和反馈中提取决策、待办与复盘报告 | 是否遗漏事项，是否编造负责人或时间 |

## 进阶实践

有一定基础后，可以根据兴趣选择以下方向深入，并与已有实现比较：

- **多 Agent 协作：**将可独立处理的子任务分给不同 Agent，比较单 Agent 与多 Agent 的效果、耗时和用量。
- **浏览器与计算机操作：**在测试环境中完成跨页面任务，验证操作是否生效，并处理页面变化和执行失败。
- **长期运行与主动任务：**参考 OpenClaw 等项目，实现定时触发、进度保存、失败恢复和重复执行控制。
- **自定义 MCP 服务：**把自己编写的工具封装成 MCP 服务，让其他客户端也能调用。
- **记忆与技能迭代：**从失败记录提炼规则，比较改动前后的收益、误触发与冲突。

按阶段查阅以下文档，结合自己的项目运行示例：

- MCP：[官方架构说明](https://modelcontextprotocol.io/docs/learn/architecture)。

选择工具时先确认可访问性、模型兼容性和费用，记录实际使用的版本与配置。平台体验可按现有账号条件选择；扣子的编程入口已有调整，使用时参考[当前官方说明](https://docs.coze.cn/cozespace_5uu7ba6t)。
