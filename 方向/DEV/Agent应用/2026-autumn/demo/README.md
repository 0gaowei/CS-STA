# Agent 应用实践与 Demo

这里收集 Agent 应用方向的实践项目，供大家自学时参考、尝试和交流。欢迎自愿分享学习中的小工具、Skill、工作流或 Agent 应用，也欢迎记录没有解决的问题和踩坑经验。

学习内容可参考本学期的 [学习路线](../Roadmap.md)。

## 按项目组织目录

**一个项目一个目录，目录用项目名称命名。**建议采用简短、能说明用途的名称，例如 `research-assistant`、`terminal-assistant`。作者、GitHub 账号和分工写在各项目的 `README.md` 中。

下面以 `research-assistant` 为例，文件按项目实际需要组织：

```text
demo/
├── README.md                    # Demo 索引与分享说明
└── research-assistant/          # 项目名称
    ├── README.md                # 项目介绍、使用方式、作者信息
    ├── src/                     # 源码（如有）
    ├── examples/                # 输入输出示例（可选）
    ├── requirements.txt         # Python 依赖（如适用）
    └── .env.example             # 不含真实密钥的配置示例（如适用）
```

Skill 可以直接保留自己的 `SKILL.md` 和资源目录；平台搭建的项目可以放工作流导出文件、配置说明和效果示例。目录重名时，可按用途或实现方式补充名称，例如 `research-assistant-mcp`。

## 项目 README 写什么

让其他人看懂项目做什么、怎样尝试即可。可以参考仓库的 [项目说明模板](../../../../../templates/demo_project_readme_template.md)，按实际情况取舍：

- **用途：**解决什么问题，适合什么场景。
- **实现方式：**使用的模型、工具、平台或框架，以及主要处理流程。
- **使用方法：**环境与依赖、配置步骤、启动方式；平台项目说明如何导入或体验，Skill 说明如何安装和触发。
- **效果示例：**给出输入和对应输出，也可以附截图、录屏或体验链接。
- **已知问题：**哪些场景效果不稳定，遇到了什么限制，有哪些后续想法。
- **作者与来源：**注明作者、GitHub 链接或小组分工；参考或改造其他项目时附上来源，并遵守原项目许可。

有做过对照实验或评测的话，也可以附上案例与结果，方便其他人判断是否适合自己的需求。

## 如何分享

1. 在 `demo/` 下新建以项目名称命名的目录，放入项目文件和说明。
2. 在下方列表中添加项目简介、实现方式和相对目录链接，作者信息放在项目自己的 README 中。
3. 通过 PR 分享，简要说明新增或修改了什么。Git 操作可参考 [仓库协作说明](../../../../../README.md#协作模式)。

提交前检查配置与示例数据，API Key、含真实凭据的 `.env` 文件和个人敏感信息请保留在本地。需要配置凭据的项目提供不含密钥的示例，并在 README 中说明填写方式。
